AI Vehicle Maintenance Assistant (Local LLM & RAG)

본 프로젝트는 외부 유료 API나 복잡한 클라우드 인프라 의존성 없이, Docker 환경에서 로컬 LLM(Ollama - Llama 3 / Llava 멀티모달 비전 모델)과 RAG(Retrieval-Augmented Generation, LangChain, ChromaDB) 기술을 유기적으로 결합하여 구동되는 독립형 AI 차량 정비 어시스턴트 시스템입니다.

단순한 텍스트 기반 챗봇을 넘어, 볼보(Volvo XC60)를 비롯한 다양한 브랜드와 차종의 소모품(에어컨/캐빈 필터, 에어크리너, 브레이크 패드, 프론트 와이퍼 등) 상태를 진단하고 공식 매뉴얼에 기반한 정확한 정비 가이드를 제공합니다. 향후 멀티 브랜드/차종 통합 확장부터 맞춤형 화이트 라벨 솔루션까지 무한히 확장할 수 있는 아키텍처로 설계되었습니다.

1. 프로젝트 기획 배경 및 동기 (Why We Built This)

현업의 문제점 체감: 자동차 정비 현장에서 일하면서 간단한 소모품 교체(에어컨 필터, 와이퍼 등)는 공임비를 포함하면 실제 부품 비용에 비해 적지 않은 비용이 발생합니다. 많은 운전자들이 방법을 몰라서, 혹은 번거로워서 비용을 지불하고 서비스를 이용하지만, 실상은 누구나 가이드를 통해 직접 해결할 수 있는 비교적 간단한 작업들입니다. 고물가 시대에 운전자들이 불필요한 공임비 부담을 덜고 실용적으로 차량을 관리할 수 있는 도구가 필요하다고 판단했습니다.

B2B 및 서비스 생태계 관점의 가치 창출:
- 고객 측면: 정비 진입장벽을 낮춰 경제적 부담을 줄이고, 다양한 차종의 신뢰성 높은 DIY 가이드와 커뮤니티 서비스를 누립니다.
- 브랜드/정비소 측면: 단순 소모품 교체로 인해 공식 서비스 센터의 예약 슬롯이 낭비되는 병목 현상을 완화하고, 전문적인 진단과 수리가 필요한 중증 결함 차량에 서비스 리소스를 집중하여 예약 주기를 단축할 수 있습니다.
- 비즈니스 확장성: 다양한 브랜드와 차종을 아우르는 범용 플랫폼 기반 위에, 완성차 브랜드별 니즈에 맞춘 맞춤형 화이트 라벨 솔루션으로 확장할 수 있는 기회를 제공합니다.
- 프라이버시와 독립성 확보: 상용 클라우드 AI를 쓸 때 발생하는 차량 정보 및 개인정보 유출 우려를 원천 차단하기 위해, 로컬 환경에서 안전하게 구동되는 독립형 정비 어시스턴트를 구축하고자 본 프로젝트를 기획하게 되었습니다.

2. 프로젝트 주요 특징 및 기술 스택
- Role: Full-Stack Architecture Design & Local AI Pipeline Orchestration
- Language & Framework: Python, Streamlit (React 전환 예정), LangChain, ChromaDB
- AI Core: Ollama (Llama 3 / Llava 멀티모달 비전 모델), YOLOv8 (프론트 와이퍼 등 커스텀 부품 감지 및 멀티 부품 가중치 최적화)
- Containerization: Docker, Docker Compose

3. 시스템 아키텍처 및 모듈화 구조 (Modular Architecture & Data Architecture)

본 프로젝트는 차량 부품 데이터의 파편화를 방지하고 향후 다양한 브랜드 및 소모품 지속 확장에 유연하게 대응하기 위해, 데이터 소스와 서비스 로직을 완전히 분리한 모듈형 아키텍처로 설계되었습니다.

소스코드 모듈화 구조 (backend/):
- app.py: 기존 Streamlit 기반 메인 웹 인터페이스 (프로토타입 및 데모 제어용)
- main.py: 향후 React 프론트엔드 연동 및 모던 웹 서비스 전환을 위해 백엔드 API 서버 용도로 새로 분리·구축한 엔트리포인트
- vision_module.py: YOLOv8 기반 커스텀 부품 인식 및 시각적 진단 처리 (front_wiper 등 추가 학습 적용)
- rag_module.py: ChromaDB 벡터 스토어 및 Ollama 기반 로컬 LLM 텍스트 RAG 파이프라인
- utils.py: 스마트 파일명 우선 검색(Exact Match) 로직 및 데이터 유틸리티 처리 (부품 인식과 가이드 매칭 정확도 극대화)

지식베이스 분리 및 파이프라인 (manual/ 및 yolo_training_data/):
- 정비 매뉴얼의 원본 Markdown(.md) 문서를 파싱하여 구조화된 JSON(.json) 데이터로 변환하는 스크립트(convert_to_json.py)와, 이를 ChromaDB 벡터 스토어에 임베딩 및 적재하는 파이프라인(ingest.py)을 분리 구축했습니다.
- 구조화된 차량별 상세 JSON 스키마 도입 (manual/volvo/xc60/): 에어컨/캐빈 필터, 에어크리너, 프론트 와이퍼 등 소모품별 정비 가이드를 단계별(steps)로 체계화한 상세 JSON 스키마를 적용했습니다. 각 단계별로 설명(description), 경고(warning), 핵심 팁(key_point)뿐만 아니라 단일 또는 멀티 이미지 경로(image)를 매핑하여, 사용자가 직관적인 시각적 가이드를 확인할 수 있도록 데이터 구조를 고도화했습니다.
- 브랜드/차종별 전용 폴더(manual/브랜드명/차종명/)에 격리 관리함으로써 새로운 차종이나 소모품이 추가되더라도 메인 비즈니스 로직 수정 없이 데이터 인프라를 무한히 확장할 수 있습니다.

도커라이징 및 환경 최적화:
- opencv-python-headless 적용을 통해 리눅스 기반 컨테이너 환경에서 발생할 수 있는 GUI 의존성(libGL.so.1) 오류를 원천 차단하고 안정적인 비전 파이프라인을 구축했습니다.
- 정비 가이드 상세 이미지 에셋(manual_images/)과 런타임 동적 데이터(uploads_images/, vector_db/, runs/)를 프로젝트 루트 레벨에서 안전하게 격리·관리하도록 구성했습니다.

4. 핵심 구현 기능 (Core Features)

로컬 멀티모달 비전 정비 어시스턴트
- 현재 상태: RAG 기반 정비 매뉴얼 텍스트 질의응답 및 로컬 환경 연동 구현 완료.
- 고도화 방향 및 구현 완료: 사용자가 부품 사진을 업로드하면 커스텀 학습된 YOLOv8 모델(best.pt)이 프론트 와이퍼(front_wiper), 에어크리너 등 부품 종류를 정확하게 시각적으로 식별하고, 최적화된 파일 매칭 로직을 통해 이에 정확히 매칭되는 차량별 상세 JSON 가이드를 불러와 소요 시간, 필요 공구, 각 단계별(Step-by-step) 상세 이미지와 주의사항을 UI에 유기적으로 렌더링하는 파이프라인을 구축했습니다.

무중단 독립형 Docker 환경 구성
- 외부 API 호출 실패나 네트워크 지연 리스크를 원천 차단하기 위해, Ollama 엔진과 웹 인터페이스를 도커 컨테이너로 묶어 어떤 로컬 PC 환경에서도 단일 명령어로 즉시 구동되도록 패키징했습니다.

5. 현실적 리스크 분석 및 방어 전략 (Risk Management)

제조사 보증 및 책임 소재 공방 리스크
- 분석: 사용자가 DIY 작업 중 부품을 오장착하여 차량 결함이 발생할 경우 제조사 보증 거부 및 책임 문제가 대두될 수 있습니다.
- 대응 전략: 정비 범위를 안전에 지장이 없는 기본 소모품 영역으로 엄격히 한정하고, UI 및 가이드 상단에 면책 조항(Disclaimer)을 배치하여 법적 리스크를 선제적으로 방어합니다.

AI 환각(Hallucination)으로 인한 오정비 방지
- 분석: LLM의 특성상 부정확한 정비 방법을 안내할 경우 차량 손상으로 직결될 수 있습니다.
- 대응 전략: 범용 답변 생성을 차단하고, 엄격하게 검증된 공식 정비 매뉴얼 텍스트 데이터베이스(ChromaDB RAG) 기반으로만 답변을 유도하여 정보의 정확도를 극대화했습니다.

기업 내부 정보 유출 및 권한 분리 리스크 (B2B 보안)
- 분석: 일반 고객용 인터페이스와 사내 직원/정비사 전용 데이터베이스가 분리되지 않을 경우, 대외비 성격의 내부 정비 지침이나 사내 데이터가 유출될 위험이 있습니다.
- 대응 전략: 사용자 권한(RBAC) 모델을 도입하여 고객용 뷰와 사내 임직원/교육용 뷰를 철저히 분리하고, 브랜드별 전용 지식베이스는 외부 접근을 원천 차단하는 데이터 격리 아키텍처를 설계에 반영했습니다.

6. 향후 확장 계획 및 비즈니스 모델 (Scalability)

- React 기반 프론트엔드 확장 (예정): 기존 Streamlit(app.py) 구조에서 벗어나 모던 웹 서비스 환경 구축 및 사용자 경험(UX) 극대화를 위해, 새로 구축한 백엔드 API 서버 엔트리포인트(main.py)와 연동되는 React 프론트엔드(frontend/) 전환을 준비하고 있습니다.
- 멀티 브랜드 및 다차종 데이터 확장 자동화 파이프라인: manual/ 하위에 브랜드별·차종별 디렉터리 체계를 구축하고, 초기 기동 시 마크다운 문서를 자동으로 파싱하여 벡터 DB에 동적 임베딩하는 자동 인덱싱 스크립트 파이프라인을 도입합니다.
- 완성차 브랜드별 맞춤형 화이트 라벨(White-Label) 및 독립 생태계 구축: 특정 완성차 브랜드와의 전략적 협업을 통해 해당 브랜드 오너들만을 위한 전용 애플리케이션으로 패키징하여 공급합니다.
- 차대번호(VIN) 기반 인앱 실시간 리콜 조회 시스템: 프로그램 내에서 차량번호 및 차대번호(VIN)를 직접 입력해 리콜 대상 여부와 공식 조치 가이드를 실시간으로 확인하는 기능을 구현합니다.
- 간헐적 소음 진단 및 유저 참여형 커뮤니티 생태계: 운전자들이 직접 소음 증상을 대조하고 자가 진단 가이드를 얻을 수 있는 브랜드별/증상별 정비 사례 공유 커뮤니티 공간을 연동합니다.
- 애프터마켓 제휴 광고 및 공식 센터 원스톱 예약 시스템: 정비 주기에 구애받지 않고, 원할 때 언제든 틴팅, 블랙박스 등 차량용품 및 애프터마켓 시공 업체를 찾아보고 연계할 수 있는 타겟팅 마케팅 모델을 구축합니다. 자가 정비 범위를 넘어선 중증 정비나 점검이 필요할 때, 애플리케이션 내에서 곧바로 공식 서비스 센터 및 연계 사설 정비소를 예약할 수 있는 편의 기능을 제공합니다.

8. 사전 준비 및 설치·실행 가이드

사전 준비 사항
- Docker Desktop (필수): 로컬 PC 환경에 도커가 설치되어 실행 중이어야 합니다.

실행 방법
1. 레포지토리를 로컬 PC로 클론 또는 다운로드합니다.
2. 터미널을 열고 프로젝트 루트 폴더 경로(C:\DIY)로 이동합니다.
3. 아래 명령어를 입력하여 컨테이너 빌드 및 애플리케이션을 실행합니다.

docker compose up --build

4. 새로운 터미널을 열고 llava 모델을 다운로드합니다.

docker exec -it ollama-server ollama run llava

5. 웹 브라우저에서 아래 주소로 접속합니다.
- 접속 주소: http://localhost:8501
